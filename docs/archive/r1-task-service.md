# R1 Tasks: Attention-Aware Task Service (M0 to M4)

> **Archived.** R1 is complete and released (v0.1.0 to v0.3.0). The one open task, **M0-07** (checking the AgentPulse contract), waits on owner action O1 and is tracked in [implementation/README.md](../implementation/README.md), section 2. The decisions taken during R1 are in section 8 of that file.

Read [README.md](../implementation/README.md) first: it explains the levels (Routine, Careful, Owner), the defaults G1 to G22, and the rules every task follows. Section numbers below refer to [architecture.md](../architecture.md). Exit criteria for each milestone are in [milestones.md](../milestones.md).

Sizes: S is up to half a day, M is about a day, L is two days or more.

## M2. Outbox, AgentPulse client, and workers

Goal: a task change results in exactly one AgentPulse `/notify` call, and no call is made on the request path.

| ID | Task | Files | Done when | Level, size | After |
| --- | --- | --- | --- | --- | --- |
| M2-01 | **Repository interfaces.** `TaskRepository`, `OutboxRepository`, `TxManager` from section 5.2, plus workspace, watcher, and comment access. Interfaces only. | `internal/repository/repository.go` | Compiles; M2-02 to M2-04 implement it without changing it | Routine, S | M1-07 |
| M2-02 | **PostgreSQL task repositories.** Pool and `WithTx` helper. Task create, get, get-for-update, update guarded by `version` (zero rows updated returns `ErrVersionConflict`), list with keyset pagination on `(updated_at, id)` and filters `assignee_id`, `status`, `priority`. Lists exclude `archived`; fetch by ID does not. Watchers, comments, and workspaces. Every query filters on `tenant_id`. | `internal/repository/postgres/db.go`, `task_repo.go`, `workspace_repo.go` | Integration tests cover version conflict, cross-tenant read returning `ErrNotFound`, and pagination stability while rows are inserted | Careful, M | M2-01 |
| M2-03 | **PostgreSQL outbox repository.** Insert with `ON CONFLICT (idempotency_key) DO NOTHING`; `ClaimBatch` using `FOR UPDATE SKIP LOCKED`, setting `processing` and `claimed_at`; `MarkDispatched`, `MarkRetry`, `MarkDeadLetter`; `ReleaseExpiredLeases`; `DeleteDispatchedBefore` in batches. A status update that matches no row is success, not an error (the row may have been removed by a permanent delete, section 5.4). | `internal/repository/postgres/outbox_repo.go` | Integration test: several goroutines claiming at once never receive the same row | Careful, M | M2-01 |
| M2-04 | **In-memory repositories.** The same interfaces backed by maps and a mutex, with transaction rollback and a hook to inject a failure at a named step. | `internal/repository/memory/` | A shared test suite passes against both the memory and PostgreSQL implementations | Routine, M | M2-01 |
| M2-05 | **TaskService.** `CreateTask`, `UpdateTask`, `CompleteTask`, `ArchiveTask`, `RestoreTask`, `AddComment`, `GetTask`, `ListTasks`, following the sequence in section 3.1. Each mutation writes the task and its outbox rows (one per event per recipient) in one transaction, then sends a non-blocking wake-up signal. Creating a task in a workspace that does not exist is `ErrValidation`. No network calls. Leave a no-op hook where M5 will enqueue agent jobs. | `internal/service/task_service.go` and test | Tests: an injected outbox failure rolls the task change back; a stale version returns `ErrVersionConflict` with nothing written | Careful, M | M2-04 |
| M2-06 | **AgentPulse client.** The `Notifier` interface from section 5.2 and typed calls from section 5.5: `Notify`, `RecordFeedback`, `CreateRule`, `ListLearningSuggestions`, `ReviewLearningSuggestion`. | M2-07 | **Circuit breaker.** Opens for 10 seconds when more than 50% of the last 20 requests returned 5xx; closes after the cooldown. Takes an injected clock. | M2-08 | **Outbox relay.** The loop in section 3.2: wake-up channel plus `OUTBOX_POLL_INTERVAL` ticker, batch claim, bounded worker pool, result handling for 2xx, non-retryable 4xx, and retryable 5xx, 429, and timeout. A lease reaper returns stale `processing` rows (G1). | `internal/worker/outbox_relay.go` and test | Tests with `-race`: 8 workers and 1,000 rows deliver each key exactly once to the mock; a row failing 10 times ends in `dead_letter`; a row abandoned in `processing` is retried | Careful, L | M2-03, M2-07 |
| M2-09 | **Deadline scheduler.** The two transactions in section 3.3, each claiming tasks with `SKIP LOCKED` and inserting outbox rows with `ON CONFLICT DO NOTHING`. Archived and completed tasks are skipped. | `internal/worker/deadline_scheduler.go` and test | Test: two scheduler instances running together produce one `task.overdue` per task per day and one reminder per window; moving `due_at` produces a fresh reminder | Careful, M | M2-02, M2-03 |
| M2-10 | **Outbox cleanup.** Once a day, delete `dispatched` rows older than 7 days in batches of 5,000. | `internal/worker/outbox_cleanup.go` and test | Test: old dispatched rows are removed; pending, dead-letter, and recent rows remain | Routine, S | M2-03 |
